## 三、TTS 关键配置（实测值）

配置文件：`core/data/config/astrbot_plugin_private_companion_config.json`（UTF-8 BOM 开头，读的时候必须 `utf-8-sig`，否则 json.load 直接炸）。

### 3.1 `voice_action_config`（生效组）

```jsonc
{
  "enable_voice_action": true,
  "enable_tts_enhancement": true,
  "tts_message_scope": "replies_only",       // 只对回复生效，不碰主动消息
  "tts_synthesis_backend": "astrbot_provider",
  "tts_provider_id_zh": "breeze-voice",
  "tts_generation_mode": "fast_tag",         // 快速标签模式，不走全文重写
  "tts_voice_language": "zh",
  "tts_delivery_mode": "voice_only",         // 只发语音，不发文字副本
  "tts_conversion_scope": "partial",         // 局部转换，保留原文语气
  "tts_conversion_provider_id": "deepseek/deepseek-flash",
  "tts_frequency_control_mode": "global",
  "tts_constraint_mode": "weak",
  "tts_session_min_interval_seconds": 0.0,
  "tts_private_min_interval_seconds": 0.0,
  "tts_group_min_interval_seconds": 0.0,
  "tts_trigger_probability": 60,
  "tts_private_trigger_probability": 70,
  "tts_group_trigger_probability": 10
}
```

### 3.2 触发关键词（决定性）

```
念,读,朗读,念一下,念给我,念给我听,读一下,读给我,语音念,用语音,
开头,这一段,往下念,接着念,念完,念出来,读出来,文案,旁白,给我念念
```

命中关键词时**直接走语音，不看概率**。本次对话里「念」「接着念」「念完」「文案」多次命中，所以哪怕 `tts_private_trigger_probability` 只有 70，实际也是条条出声。

### 3.3 概率的真实表现（日志证据）

```
[TTS增强] TTS全局触发概率未命中,本轮不注入TTS提示词:
reason=streaming_preflight probability=0.70
```

也就是说：**没命中关键词、又没撞上 70% 概率的那轮，模型不会收到 TTS 指令**，只会打一行 preflight 日志。要让它稳定出声，两条路——把 private 概率调到 100，或者每句话里带一个关键词。

### 3.4 本地播放（本次关闭）

```jsonc
{ "enable_tts_local_playback": false, "tts_local_playback_volume": 35 }
```
本次交付只走 QQ 语音组件，本机不出声，避免与用户音箱抢设备。

## 四、音频切分策略

原始 2683 字按 600–700 字切成 4 段：

| 段 | 字数 | 文件大小 | 内容 |
| --- | --- | --- | --- |
| 1 | 662 | 2.45 MB | 北域边境线、妖军攻势、承平登场 |
| 2 | 684 | 2.60 MB | 承平一指点杀符念师、道士与小妖登场 |
| 3 | 698 | 2.55 MB | 妖尊殿内景、邵神韵出场 |
| 4 | 611 | 2.17 MB | 小狐狸怜儿、诊断"情窦枯萎，只能以情浇灌" |

切分规则（脚本 `split_by_chars`）：

1. 先按空行、换行拆自然段；
2. 依次累积到 600 字上限，超出则回退到最近的 `。` 后断开；
3. 单段本身超长（> 1200 字）时按句号硬切，避免一口气念到断气。

经验值：
- **500–700 字/段**是 QQ 语音的舒适区间，一段 60–90 秒，用户不会点开到烦；
- 场景切换处（战场 → 妖尊殿）**一定要断段**，不然情绪会塌；
- 字数差控制在 ±10%，四段时长才匀。

## 五、清洗与改写规则

TTS 念错字的来源基本都在清洗这一步。

### 5.1 错字对照表（`FIXES`）

| 原文 | 修正 | 原因 |
| --- | --- | --- |
| 白暂 | 白皙 | 形近字，模型读成 zhàn |
| 仍由 | 任由 | 音近，语义错 |
| 及其冒险 | 极其冒险 | 同音异义 |
| 狐狸烫 | 狐狸汤 | 汤/烫，语境是食物 |

### 5.2 符号处理

```
「」 → 删书名号，引号内内容后接逗号
“”  → 同上
* # > ` ~ [ ]  → 全删
…（2 个以上） → ……
。（2 个以上） → 。
连续空格/制表 → 单空格
```

**关键点**：中文小说里大量「」包裹的对白，如果原样送去合成，模型会在每个引号处停顿，听感像结巴。统一换成逗号后，语流立刻顺。

### 5.3 口语化改写（fast_tag 局部）

只改这三类，别的原封不动：
1. 纯书面连接词（"然而""于是"）→ 口语（"结果""紧接着"）；
2. 长定语句 → 断成两句；
3. 生僻字加法注音（"符念师"→"符念师"保持，不注音，避免破坏听感）。

保持原文的描写性语言不动，尤其"雪""血""刀""殿"这些单字意象，改了就没味道。

## 六、故障与处理

### 6.1 HTTP 503 · 产能满（16:25 首现）

```
{"error":{"code":"GENERATION_CAPACITY_EXCEEDED"}}
```
非本地配置问题，是服务端排队满了。处理：退避重试 15s × 3，仍失败则提示稍后再跑。**不要**去动 key 或 base_url，动了也没用。

### 6.2 HTTP 429 · 限流（17:36 出现）

```
urllib.error.HTTPError: HTTP Error 429: Too Many Requests
```
不要发文字"（正在合成）"，那会占用一个轮次。

### 6.3 速度与节流

脚本实测 **约 40 字/秒**，超时时间按 `len(text)/40` 动态给：

```python
timeout = max(60, int(len(text) / 40))
```

段间隔默认 2.0s；批量跑时建议 3–5s，否则容易撞 429。

### 6.4 漏段补录

用户反馈"后面几段呢"时，先 `os.listdir` 核对实际文件，**别凭记忆说已发**。本次就是靠核对 `ch46_seg*.mp3` 四个文件都在，才敢说"发过了"。重发时只补缺失段，不重录全部，省额度。

### 6.5 关键字被吃掉

`tts_trigger_keywords` 里有"开头""这一段"这种高频词，日常闲聊容易误触发。建议只保留"念/读/朗读/念完/接着念/用语音"这几条硬触发。

## 七、音频交付方式

`send_message_to_user` 一次可带多个组件，顺序即发送顺序：

```json
[
  {"type": "plain", "text": "后两段补发。"},
  {"type": "record", "path": "audio/ch46_seg3.mp3"},
  {"type": "record", "path": "audio/ch46_seg4.mp3"}
]
```

注意：
- `record` 必须绝对路径，相对路径在某些实现下会失败；
- 一条消息里塞 3 段以上，部分客户端会只播第一段，**建议每次不超过 2 段**；
- 发完不要重复输出同一句附言。

## 八、独立脚本 `scripts/tts_batch.py`

脱离 AstrBot 也能跑，方便批量出稿。

```powershell
$env:BREEZE_API_KEY="brz_xxx"
$env:BREEZE_TTS_VOICE="voc_xxxxxxxx"
python scripts/tts_batch.py --input chapter.txt --out ./audio --max-chars 700 --gap 3
```

内置：
- `clean()` 清洗
- `split_segments()` 分段
- `probe()` 3 字探活（返回 > 5KB 视为可用）
- `synth_with_retry()` 503/429 分支退避
- 输出 `manifest.json`（含 index / chars / bytes / head / tail）

## 九、可复用清单

1. 先探活，再批量——3 个字，5 秒，能省一轮白跑。
2. 配置文件带 BOM，一律 `encoding="utf-8-sig"`。
3. 引号「」必删，换逗号。
4. 500–700 字/段，场景切换必断。
5. 关键词触发优先于概率，稳定出声靠关键词。
6. 用户说"没收到"，先查文件再看日志，别认错也别狡辩。
7. 429 偶发是常态，退避 15s 起，别只重试 0.2s。
8. 一次最多发 2 段语音，多了会吞。
